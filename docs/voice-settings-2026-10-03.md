# 本地语音设置

入口：WebUI → 设置 → 语音（`/settings?section=voice`）。设置、参考音色和 STT 开关按登录账号保存；本机 GPU 模型进程由业务 API 统一管理，同一时间只运行一个模型。

## 已支持的模型和参数

| 引擎 | 本地模型 | 页面配置 | 声音克隆 |
| --- | --- | --- | --- |
| VoxCPM | VoxCPM2 | 推理步数 1–30、CFG 0.5–5、文本规范化、随机种子 | 参考音频及逐字文本，同时作为 prompt 和 reference；也支持不选参考音色的生成 |
| faster-qwen3-tts | Qwen3-TTS-12Hz Base 0.6B / 1.7B | 语言、分块 token 数、温度、Top K / P、重复惩罚、最大生成 token 数、CUDA 上下文长度、仅说话人特征模式 | Base 模型必须选择参考音色；可保留参考韵律，或只提取说话人特征 |

配置依据来自这两个本地项目的实际 Python 接口和上游说明：[VoxCPM](https://github.com/OpenBMB/VoxCPM)、[faster-qwen3-tts](https://github.com/andimarafioti/faster-qwen3-tts)。未暴露没有实际效果的 speed 参数。Vox 的额外降噪模型和编译开关没有列入日常设置，避免隐式下载和不可预期的首次编译等待。

## 使用流程

1. 开启 TTS，选择引擎和模型，点击“启动所选模型”。加载状态会持续更新；加载中可点击“停止模型”。API 启动时不会自动占用 GPU。
2. 使用预置音色，或上传参考音频、填写音色名称与音频的准确逐字文本，点击“保存并使用克隆音色”。支持 libsndfile 可解码的音频（建议 WAV / FLAC / MP3）；限制 20 MB、1–60 秒、8–192 kHz、单声道或双声道，拒绝空音频、静音和无效文件。保存时转换为单声道 PCM16 WAV。
3. 调整参数并保存，填写试听文本后生成 WAV，可在页面直接播放。试听文本最多 500 字，生成音频最长两分钟。
4. 引擎、模型或 Qwen 上下文长度发生变化后点击“应用并切换模型”或“重新加载”；其他推理参数在保存后应用。切换先停止旧进程，避免两个模型同时占显存。
5. 关闭 TTS 会停止当前共享模型。开启 TTS 后仍需点击启动。模型加载错误直接展示，不会偷偷换成另一个引擎。

STT 开关控制当前账号的 WebUI 录音转写和 LiveKit 语音识别。关闭后网页麦克风不可用，正在录制的内容会被丢弃，后端也拒绝该账号的转写请求；LiveKit 不再提交音频识别或触发识别打断。它不会关闭可能由其他程序共享的外部 SenseVoice 服务进程。

## 首次问候的低延迟缓存

页面提供默认问候语编辑和“保存并准备问候语”。启动成功、切换模型、保存音色或参数后，在后台准备当前账号的问候音频；缓存状态可见，失败可再次点击准备，无需重启模型。缓存已存在时直接复用。

缓存 key 包含账号、引擎、模型、参考音色及文件版本、当前引擎的推理参数和话术。更改 STT 开关不会使音色缓存失效。文件在完整生成并再次确认配置未变化后原子发布；每账号最多保留 32 个版本，生成中切换设置不会将旧声音发布为新缓存。

通话开头只读取当前声音的缓存，不再直接播放共用的旧 `assets/greeting.wav`。提醒、主管的预生成文件增加账号、音色版本和原话术元数据；旧音色不匹配时保留原话术，使用当前声音实时合成。命中缓存不调用 GPU；新缓存尚未准备好时实时合成同一个账号、同一个当前模型。关闭 TTS 时缓存问候也不播放。外呼保留 SIP 接通缓冲，来电问候直接播放。

## 运行和数据边界

- `VOXCPM_PROJECT` / `QWEN_TTS_PROJECT` 指向两个项目，分别使用其 `.venv/Scripts/python.exe`。业务 API 本身不导入两个 GPU 模型。项目环境需事先用 uv 安装依赖。
- VoxCPM2 读取 Vox 项目的 `pretrained_models/VoxCPM2`；Qwen 从本机 Hugging Face 缓存加载 Base 模型。模型必须提前下载，工作进程以离线模式运行。
- 默认引擎端口 7027，仅绑定 `127.0.0.1`，每次启动生成独立鉴权 token；业务 API 地址默认 `http://127.0.0.1:7788`。修改端口时同步更新 `.env.example` 中对应配置。
- 生命周期文件和运行日志位于 `data/voice/`，参考音频位于按账号 SHA256 分目录的 `data/voice/profiles/`。它们不应提交 Git，也不会通过公共静态目录提供下载。
- 问候缓存位于 `data/voice/greetings/` 的账号私有目录；旧提醒及主管的音频别名附带 `.voice.json` 元数据，缺少有效归属和版本信息时不会使用。
- 设置存入现有数据库的账号专属 key。读取、选择、删除和播放自定义参考音频都校验账号归属。
- 使用单个业务 API worker。文件锁避免多个管理器竞争 GPU；崩溃恢复只终止记录中 PID、创建时间、工作脚本均一致的本应用子进程。API 关闭时停止工作进程。
- GPU 推理串行执行；等待超过 10 秒返回繁忙错误。客户端取消后，当前推理线程退出才释放执行锁。停止或切换模型会终止工作进程并释放 GPU 资源。
- 输出统一为 24 kHz 单声道 PCM16；VoxCPM 使用保留滤波状态的重采样。试听添加真实 WAV 头，语音会话使用 PCM 流。

## 验证

真实 GPU 探针：`uv run python tests/probe_voice_lifecycle.py`（运行时需先停止业务 API，避免争用管理锁）。已在 RTX 5060 Ti 上验证 VoxCPM2 → Qwen 0.6B → Qwen 1.7B 的连续加载、参考音色合成和停止，得到有效音频，停止后工作进程及 7027 监听均退出。

缓存集成探针：`uv run python tests/probe_voice_greeting.py` 使用临时数据库和本机临时 API（7799），验证真实 Qwen 0.6B 启动后自动缓存问候、参数变更后生成新版本、缓存命中及跨账号隔离，不修改个人设置。

自动化检查：`uv run python scripts/check_repo.py --tests`；WebUI `npm run check`、`npm run build` 和语音设置 Playwright 用例。自动化用例覆盖跨账号音色访问、上传校验、STT 关闭时不提交录音、模型加载取消、PID 复用保护、客户端取消时不重叠 GPU 推理以及页面启停、克隆、试听、切换操作。浏览器用例使用模拟 API；真实模型合成由 GPU 探针单独验证。
