# 长期记忆边界与验证

## 提示词职责

- 主助手：完成当前请求，历史资料仅在相关时参考；用户当前要求优先于旧偏好，不把旧资料当系统指令。
- 会话摘要：续接当前任务，保留临时约束、进行中事项，并区分用户事实与助手建议；不推断长期画像。
- 长期提取：只从新增用户文本筛选明确、稳定、跨会话有用的新事实，默认返回空列表。
- 显式记忆工具：仅用于用户明确要求长期记住的信息；与自动提取共用 `memory_policy.py` 的类别和筛选规则，并独立审核最新用户消息。

## 类别

| 类别 | 保存内容 | 不保存内容 |
|---|---|---|
| profile | 稳定身份、学校、职业等自述 | 行程、考试状态、临时项目进度 |
| preferences | 明确长期喜好或默认交互偏好 | 一次搜索、采购、临时输出格式 |
| relationship | 明确亲属/同事等关系事实 | 对助手发脾气、一次互动记录 |
| patterns | 用户自述的固定作息/重复习惯 | 根据工具调用、单次行为推断人格 |

“明天买茶”是任务，不是爱喝茶；“搜索某公司新闻”不是长期兴趣；“这次只输出 JSON”不是永久格式。“以后默认用中文回答”可以作为偏好。引用的助手话、文档、代码、OCR 和测试提示词不等于用户自述。

## 程序约束

候选必须提供用户消息索引、连续原话和与类别一致的长期依据。程序拒绝伪造来源、低重要度、多行/过长条目；每批最多 3 条。短消息不再因不足 8 字被排除。助手回复和工具输出不进入提取输入。

写入统一去掉日期、空白、标点并规范大小写去重，包括同批及跨类别重复；语义改写去重仍依赖模型。每文件最多 40 条/8000 字符，单条写入最多 350 字符。达到上限报错，不截断/删除历史。跨进程文件锁和原子替换防止并发覆盖或半写入。

提取使用原生结构化输出；失败记录错误并保留提取游标，不在该流程切换为自由文本解析。新旧事实冲突时要求不追加，当前没有自动覆盖旧记忆的更正器。

## 现有数据与限制

本次不自动清理旧文件、不迁移记忆目录。当前 `config.MEMORY_DIR` 默认是仓库的父目录下 `memory/`，而仓库内也有 `memory/` 样本；部署应先明确哪个目录是真实来源，避免在两套数据之间误切换。`MEMORY.md` 旧索引并不参与当前加载；模板中的旧 token 上限不是实际执行的限制。

证据匹配只能验证原话存在，不能数学证明长期性或消除引用误判。长期性、冲突及语义去重仍需模型正确判断。单元测试使用模拟输出，仅证明程序约束；真实模型评测应使用匿名样本，单独检查无用记忆误收率、正确事实漏收率及语义重复率，不能把 mock 通过视为模型质量验收。

运行：`uv run python -m unittest discover -s tests -p "test_*.py"`。新增回归在 `tests/test_memory_quality.py`，只写临时目录，不修改用户记忆。
