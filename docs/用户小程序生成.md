# 用户小程序生成（本机第一阶段）

聊天请求“创建一个番茄钟小程序”会调用 create_standalone_mini_app。编码模型输出独立的 HTML、CSS、JavaScript；后端校验结构和大小，拒绝把主容器锁在窄屏宽度的 CSS，并用 node --check - **仅解析** JavaScript 语法，不在 Python/Node 进程里运行生成代码。一次无效输出允许模型修复一次；仍失败则记录明确错误，不发布其他版本。

用户应用保存在 user_apps，候选与已发布版本在 user_app_revisions，生成状态与阶段在 user_app_jobs。所有查询和发布都需要认证后的 user_id。旧的待办时间线自动迁移成 catalog 类型版本，保留原应用 ID，读取已发布版本作为唯一配置来源。独立代码是 html 类型版本；生成成功只进入待预览状态，用户必须在右侧工具箱点击“运行草稿预览”，随后手动点击“发布这个版本”。已发布的旧式窄屏小程序可用“生成响应式草稿”创建下一版本；原版本保持发布状态，待用户预览后再决定是否发布新版。响应式修订在 API 进程内后台运行；若服务重启，未完成的修订会标记失败并允许重试，不会卡在“生成中”。

前端把代码放进仅允许脚本、不允许同源权限的 sandbox iframe，并用 CSP 阻止网络、外部资源、表单和嵌套框架。不向 iframe 传 JWT、真实待办、邮件或其他个人数据。放大预览使用真实宽高而非 CSS 缩放；生成提示要求代码自行适配窄栏和宽屏。旧版中写死的 320px 布局不会被前端自动改写。生成小程序没有持久存储，切换/刷新后内部状态会丢失。原时间线仍使用受信任的 json-render 组件读取本人待办；不要把它当作可任意访问私人数据的代码小程序。

本阶段的语法检查不是完整功能测试或恶意代码审计。浏览器沙箱无法保证无限循环等代码不会拖慢本机标签页。需要真实数据、服务端执行、可靠的资源配额或多租户生产发布时，应增加独立执行环境与显式授权的数据能力接口，不要直接开放主进程、主站令牌或数据库给生成代码。

验证命令：后端运行 uv run python -m unittest discover -s tests -p "test_*.py"；前端运行 node --experimental-strip-types --test src/lib/generated-app-document.test.ts 和 npm run build。
