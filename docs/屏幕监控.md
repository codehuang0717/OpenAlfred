# 屏幕监控部署与验证

## 本机绑定与启动

本机目录已有 Screenpipe 0.3.6 二进制。启动参数明确禁用录音，并使用 Windows Native OCR；但该版本仍会初始化语音模型。若二进制缺失，设置 `SCREENPIPE_EXE` 为兼容的 Windows CLI 可执行文件绝对路径；缺失会明确报错，不会自动下载或替换程序。

1. `uv sync` 安装锁定的 Python 依赖。
2. 执行 `./start-all.ps1`，或在已有服务栈上单独运行 `uv run python src/supervisor.py`。不要重复启动；未绑定时 Supervisor 保持等待，不录屏。
3. 在这台 Windows 电脑上打开 `http://localhost:3000`，登录后进入“设置 → 主管设置”，点击“绑定到当前登录账号”。在 Windows 确认框核对用户名及账号 ID，再选择“是”；默认选项为“否”。绑定本身不会开启录屏。
4. 绑定会保存到 `data/screenpipe/device-binding.sqlite3`，各服务实时读取，无需改 `.env` 或重启。随后手动开启“主动记录”，确认状态变为“屏幕记录中（不录音）”后，再按需开启“智能监督”。升级本次代码需要先重启一次旧服务。

未绑定会拒绝采集及查询；新的用户级开关默认全部关闭。旧全局开关不会沿用，也不会自动把旧录屏归属给某个用户。绑定只使用认证身份，不接受客户端指定用户 ID；已有绑定不能由另一个账号覆盖。

`SCREEN_MONITOR_USER_ID` 仍可用于管理员预配置。若它与已保存的绑定冲突，会明确报错，不选择某一个继续运行。当前没有远程解绑/换绑接口，需要由本机管理员在停止服务后处理归属。

远程 IP、远程 Origin 或包含外部来源的转发头会被拒绝。由于本机代理也可能转发远程请求，HTTP 检查不是授权依据；必须通过 Windows 桌面确认框完成实际授权。无交互桌面的 Windows 服务无法完成此流程。确认时页面会显示等待提示，请及时处理确认框；若代理超时，页面后续刷新仍会读取最终绑定结果。

## 数据与边界

- 新数据位于 `data/screenpipe/users/<账号ID的SHA256>/`；原来的 `data/screenpipe/` 数据不删除、不迁移、不查询。
- 仅绑定账号可以控制监控、查询历史及调用即时截图工具。即时截图属于用户主动请求，不依赖连续记录开关，但同样校验归属。
- 智能监督只读取绑定账号的待办。OCR 获取失败或无数据时不会调用模型；智能监督开启后，OCR 文字会发送到配置的云端模型，并可能触发语音提醒。
- `SCREENPIPE_URL` 仅支持明确端口的本机 HTTP 地址。**Screenpipe 原生接口不是多租户鉴权接口，不要将 3030 端口反向代理或开放给局域网/公网；Windows 防火墙应阻止外部访问。**这里的隔离是 OpenAlfred 账号级隔离，不是针对本机管理员或本机其他程序的 OS 安全隔离。

## 状态与排障

页面每 5 秒刷新服务状态；Supervisor 每 3 秒检查开关，分析在独立任务中运行，关闭开关会取消分析。状态同时检查心跳、可执行文件路径、用户数据目录、监听端口和 `/health` 的 OCR 状态，不把开关值当作运行状态。

启动失败/采集进程退出会展示原因，停止重启尝试。修复后先关闭记录，等待至少一次状态刷新，再重新开启；重启 Supervisor 也会清除这次进程内错误。不会接管或杀掉其他 Screenpipe 进程。Supervisor 退出时关闭自己启动的采集进程；异常退出由 Screenpipe 的 `--auto-destruct-pid` 处理。

- Supervisor 日志：`logs/supervisor.log`；一键启动的输出：仓库根目录 `supervisor-stdout.log`、`supervisor-stderr.log`。
- 采集日志：对应用户目录中的 `screenpipe.log`。若出现 `Protobuf parsing failed`，检查 `%LOCALAPPDATA%\screenpipe\models\` 中的 `.onnx` 是否实际上是 HTML 页面。0.3.6 即使使用 `--disable-audio` 仍可能从已失效的 GitHub 路径下载这两个文件。已验证可用的 WeSpeaker 模型来自 [sherpa-onnx 发布文件](https://github.com/k2-fsa/sherpa-onnx/releases/download/speaker-recongition-models/wespeaker_en_voxceleb_CAM++.onnx)，SHA256 为 `c46fad10b5f81e1aa4a60c162714208577093655076c5450f8c469e522ec54ef`；分割模型来自 [Hugging Face 模型文件](https://huggingface.co/altunenes/modelsfolder/blob/main/segmentation-3.0.onnx)，SHA256 为 `b78fc48113bb46fd247ae6a9aea737079550c647638db961df7e0e1e9f4ba62e`。替换前保留原文件，下载后核对哈希。
- 不录屏的安装：`./src/body/windows_system/eye/setup_eye.ps1 -InstallModels` 仅在模型缺失或校验失败时下载固定版本并核对大小和 SHA256，原无效文件保留为 `.invalid-*`。`-CheckOnly` 只检查二进制及模型缓存，不开启采集；实际 OCR 须在用户开启记录后，以 `/health` 的 `frame_status=ok` 和 `/search?content_type=ocr` 的结果验证。

## 自动化测试

```powershell
uv run python -m unittest discover -s tests -p "test_*.py"
```

测试使用临时数据库、模拟采集进程和网络，不读取真实屏幕、不调用模型。真实采集验收需绑定账号后由用户打开开关，检查 OCR 就绪、历史查询和关闭后进程退出。
