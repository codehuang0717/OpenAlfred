# OpenAlfred 功能说明

> 依据当前代码（后端 `OpenAlfred` + 前端 `OpenAlfred-WebUI`）整理，供功能测试使用。
> 生成日期：2026-09-05。README 与实现不一致处已单独标注。

本文描述的是**产品当前能做什么**，不是设计愿景。测试时以「预期行为」为准。

---

## 1. 产品是什么

OpenAlfred 是一套**自部署的主动型 AI 私人助理**：

- 你在网页里对话，它能记待办、设提醒、查邮件、搜知识库、查天气、上网搜索。
- 后台可以盯屏幕：发现你在摸鱼且有进行中的任务时，会打电话过来。
- 提醒到期可以推 iOS（Bark）或打电话。
- 语音走 SIP 软电话或本机唤醒词，不在浏览器里打电话。

**运行时拓扑（测试前需要知道哪些进程在跑）：**

| 进程 | 默认端口 | 测什么时必须有 |
|---|---|---|
| FastAPI 业务 API | `:7788` | 几乎所有 Web 功能 |
| LangGraph Agent | `:2024` | 对话流式、工具调用 |
| Next.js WebUI | `:3000` | 全部页面 |
| Redis | `:6379` | 提醒到期、SSE 实时刷新 |
| Worker | — | 提醒/待办到期调度 |
| LiveKit Server | `:7880` | 语音通话、唤醒词 |
| LiveKit Voice Worker | — | SIP / 本地语音会话 |
| Supervisor | — | 分心监测来电 |
| Ear（唤醒词） | — | 「Alfred」唤醒本机对话 |
| Screenpipe（Eye） | `:3030` | 屏幕 OCR / 智能监督 |
| SenseVoice STT | `:8000` | 通话听写、聊天麦克风 |
| TTS | `:7017` | 通话说话 |

## 2. 页面与入口

前端只有这些路由：

| 路由 | 作用 |
|---|---|
| `/` | 立刻跳到 `/chat` |
| `/login` | 登录 |
| `/register` | 注册；成功后可能展示 SIP 分机号/密码 |
| `/chat` | 新对话（发第一条消息才真正建线程） |
| `/chat/[threadId]` | 已有对话 |
| `/settings` | 设置（分区靠客户端切换，不是子路由） |
| `/knowledge` | 知识库全页 |

聊天页右侧工具箱（邮件 / 待办 / 提醒 / 通话 / 知识库）**没有独立 URL**。设置里的「个人中心、Agent、SIP、邮箱、模型、语音、通知、主管、教程」也没有独立 URL，可用 `?section=tutorial` 打开教程分区。

**没有的东西（不要当成已实现去测）：**

- 浏览器内 LiveKit 通话页
- PWA / Service Worker
- 暗色模式开关
- 独立 Dashboard 页（前端 README 写过，代码里没有）
- 设置里「语音」分区目前是占位文案：「TTS 语音合成设置即将推出」

## 3. 账号与鉴权

### 3.1 注册

- 用户名至少 2 位，密码至少 6 位，显示名可选。
- 成功后发 JWT，写入 `localStorage.token` 和 cookie `token`（24 小时，SameSite=Lax）。
- 同时自动分配 SIP 分机（从 101 起；100 留给主管来电），并可能刷新 Asterisk `pjsip_users.conf`。
- 若响应带 SIP 凭证：页面展示分机号、密码（可复制）和 Zoiper 配置说明；无 SIP 则只显示注册成功。
- 点「进入聊天」进入 `/chat`。

### 3.2 登录

- 用户名 + 密码。
- 成功后同样发 JWT，更新 `last_login_at`。
- 最近登录的用户会被主管进程、部分天气回退逻辑当成「当前活跃用户」。

### 3.3 会话与退出

- 无 cookie → 被拦到 `/login`。
- API 401 → 清本地登录态并跳登录页。
- 「退出登录」只清本地，**没有服务端 logout 接口**。
- 没有角色、没有管理员账号。所有登录用户权限相同。

### 3.4 个人资料

入口：设置 → 个人中心。

- 改显示名。
- 上传头像：图片 ≤5MB，服务端中心裁剪成 256×256 JPEG。
- 改密码：需旧密码，新密码至少 6 位。
- 用户名、SIP 分机号只读。
- 刷新 token：`POST /api/auth/refresh`（前端菜单里不一定暴露）。

## 4. 对话

### 4.1 新对话与历史对话

- `/chat` 空态：问候语；若已保存天气位置则显示天气卡；4 条建议芯片（建待办 / 提醒开会 / 图文笔记 / 随便聊聊）。
- 发出第一条消息时才创建线程，URL 变成 `/chat/{id}`。
- `/chat/{id}` 先拉历史再继续聊。
- 流式结束后根据首条用户消息自动生成侧栏标题（中英均可，偏短）。

### 4.2 流式回复

- 前端直连 LangGraph `POST /threads/{id}/runs/stream`，带 Bearer JWT。
- 可见：token 逐字出现、加载动画、停止生成。
- 不可见（不要当成漏消息）：`extract_knowledge`、`summarize` 节点输出不进气泡。
- 助手回复支持 Markdown、表格、KaTeX、代码块悬停复制。
- 助手气泡可复制全文。消息里的图片可点开灯箱。

### 4.3 工具调用展示

对话中工具调用以行内摘要显示（调用中旋转 / 完成后打勾），覆盖 Memory、Todo、Reminder、Search、Email、知识库等。

右侧待办/提醒等面板会在工具执行后和 SSE 事件到达时刷新。

### 4.4 附件

- **图片**：回形针、粘贴、拖放。以 `image_url`（base64）进 LangGraph 消息，**不走单独上传接口**。
- **非图片文件**：先 `POST /api/parse-file` 抽文本再作为 `file_text` 发给模型。支持 PDF / DOCX / 纯文本。抽文本**不入库知识库、不处理图片**。

### 4.5 聊天麦克风（不是打电话）

输入框麦克风：录音 → WAV → `POST /api/transcribe`（SenseVoice）→ 填进输入框。用户仍要点发送。依赖 STT 服务。

### 4.6 模型选择

- 输入框上方 pill（仅当可用模型多于 1 个才显示）。
- 设置 → 模型：卡片选择；本地 Gemma 会显示 Ollama 是否在线。
- 目录由已配置的 API Key 决定，可能包括：`gpt-cloud`、`cerebras`、`gemini`、`deepseek`、`deepseek-pro`、`mimo`、`gemma-local`。
- **当前是全局设置**（`settings.model_selection`），不是按用户隔离。多用户同时测会互相覆盖。

### 4.7 线程侧栏

- 新建、按标题搜索、按「今天 / 7 天 / 30 天 / 更早」分组。
- 重命名、删除（有确认）。
- 通话类线程（`metadata.type=call`）**不出现在对话列表**，只在右侧「通话」里。
- 线程按 JWT 里的用户隔离。

### 4.8 首次引导

未看过引导的用户打开聊天会弹出：欢迎 →「看教程」或「以后再说」。状态存在 `users.onboarding_seen`。

## 5. Agent 能调用的能力（对话工具）

文字对话绑定全部工具。语音通话会去掉：`make_outbound_call`、`get_recent_emails`、`read_email`、`get_email_accounts`。

| 工具 | 用户可观察到的行为 |
|---|---|
| `get_todos` / `add_todo` / `update_todo` / `delete_todo` | 查/建/改/删待办；可带 emoji、备注、期望完成时间、计划开始时间 |
| `list_reminders` / `add_reminder` / `update_reminder` / `cancel_reminder` | 提醒可走 **push（Bark）** 或 **call（电话）** |
| `make_outbound_call` | 经 LiveKit SIP 打给用户分机（语音通话中禁用） |
| `get_user_profile` / `get_user_memory_category` / `update_user_memory` | 读/追加长期记忆 |
| `get_email_accounts` / `get_recent_emails` / `read_email` | 列账户、列最近邮件、读全文。返回的结构化块给前端渲染 |
| `web_search` | Tavily 搜索，默认约 5 条 |
| `search_knowledge` / `list_knowledge` | 知识库语义检索 / 列出已入库文档 |
| `get_weather` | Open-Meteo；可用已存位置或临时地点 |
| `view_screen` / `search_screen_time` | Screenpipe：当前屏 / 历史 / 时间窗 OCR |
| `take_screenshot` | 截当前屏并用视觉模型回答 `query`（不写入知识库） |

**Agent 不能直接发邮件。** 它只能起草；用户必须在聊天里点确认，前端才调用发送接口。

## 6. 待办

### 6.1 创建

主要通过对话（「帮我记一下……」）。右侧面板没有「新建待办」主按钮。

字段：标题、描述、emoji、备注、状态（`pending` / `completed`）、期望完成时间、计划开始时间。软删除。

### 6.2 右侧面板

- 勾选完成 / 取消完成。
- 编辑标题、描述、开始时间、截止时间。
- 删除。
- 已完成项折叠。
- SSE `todo.*` 到达时自动刷新。

### 6.3 到期行为（当前实现）

Worker 到期扫描到待办后：**只标记 `notification_sent`，并唤醒 Supervisor。不发 Bark。**
代码注释写明「按用户要求不再给 Todo 发 Bark」。README 里「逾期催促」容易让人以为会推送，测试时不要按推送来测。

主管进程只在用户有**已到计划开始时间、仍 pending** 的待办时，才会做分心监测来电。

## 7. 提醒

### 7.1 创建

主要通过对话。可指定：

- 时间、标题、正文、副标题
- 紧急程度：`active` / `timeSensitive` / `passive` / `critical`
- 提示音
- 送达方式：`push` 或 `call`（电话可带开场白）

### 7.2 右侧面板

- 改时间、删除。
- 标签区分电话 / 推送。
- 过期高亮。
- 已发送项折叠。
- SSE `reminder.*` 刷新。

### 7.3 到期送达

- `push`：发到该用户 `bark_url`；未配置时明确报错并保留提醒为未发送。
- `call`：SIP 外呼用户分机；电话失败时会尝试 Bark 兜底。
- 电话提醒可能预合成 TTS 缓存到 `assets/audio_cache`。

依赖：Worker + Redis；push 还要 Bark；call 还要 LiveKit / SIP / TTS。

## 8. 邮件

### 8.1 绑定账户

设置 → 邮箱集成：

- 支持多账户。预设：Gmail / QQ / 163 / 其他（自定义 IMAP/SMTP）。
- 保存前先验证 IMAP + SMTP，通过才写入。
- 密码用 Fernet 加密（`EMAIL_ENCRYPTION_KEY`）。
- 可断开账户。
- 网易/QQ 等会在登录后发 RFC 2971 IMAP ID，否则可能被拒。

### 8.2 阅读

- 对话：「最近邮件」「看某封信」→ 工具返回结构化块。
- 前端把 \`\`\`email_list\`\`\` / \`\`\`email_content\`\`\` 渲染成列表卡 / 摘要卡。
- 右侧邮件面板：按账户分组；点开 Dialog 用 iframe 看正文。

### 8.3 发送（必须人工确认）

- Agent 用 \`\`\`email_draft\`\`\` 起草。
- **只有最新一条草稿可点发送**；旧草稿失效。
- 点发送才 `POST /api/emails/send`。

## 9. 知识库（RAG）

### 9.1 入库

两个入口：全页 `/knowledge`，以及聊天右侧迷你列表。

| 方式 | 行为 |
|---|---|
| Web 上传 | 选文件后 `POST /api/rag/upload`，202 后台任务，轮询进度 |
| 本机路径 | 浏览（Windows 原生文件框）或手输绝对路径 → `ingest-path`。同一路径对同一用户会跳过重复入库 |
| 纯文本 API | `POST /api/rag/ingest-text`（UI 不一定暴露） |
| CLI | `uv run python -m rag.cli ingest / search / list / delete` |

Web 上传接受：`.md .txt .py .js .ts .json .yaml .yml .csv .html .css`。

**Markdown 管线（完整）：** 按标题切段 → 复制图片 → MiMo 视觉模型生成中文描述（按文件 SHA256 缓存）→ BGE-M3 向量化 → ChromaDB。检索时把占位符还原成可显示的图片 URL。

**PDF / DOCX：** 仅「本机路径入库」`ingest-path` 会抽文本再当纯文本入库，**不走图片描述**。聊天附件解析 PDF 只给当前对话看，不入库。

### 9.2 管理与检索

- 列表：标题、类型、chunk 数、日期；可删除（向量 + 图片一起删）。
- 页面内搜索测试：Top-K、Resolved / RAW、分数色标。
- 对话中：`search_knowledge` 引用笔记；命中带图的 chunk 时应还原图片。
- 知识库图片：`GET /api/images/{doc_id}/{filename}`（需登录，防路径穿越）。

用户之间的文档隔离。

## 10. 长期记忆

文件系统：`memory/{user_id}/`

| 类别 | 文件 | 何时进入模型 |
|---|---|---|
| 基本信息 | `profile.md` | 每轮自动注入 system prompt |
| 偏好 | `preferences.md` | 每轮自动注入 |
| 行为模式 | `learned_patterns.md` | 仅工具按需读取 |
| 关系 | `relationship.md` | 仅工具按需读取 |

**自动抽取：** 大约每 `EXTRACTION_INTERVAL`（默认 3）轮对话，从足够长的消息里抽事实并追加。语音通话不做摘要压缩。

**中期摘要：** 对话超过阈值时压缩旧消息，写入 `thread_memories`。语音通话跳过。

**手工编辑：** 设置 → 个人中心 → Memory 四个 Tab，Markdown 整篇覆盖保存。

## 13. 语音通话（不在网页里打）

### 13.1 你打给 Alfred（呼入）

1. 用 Zoiper / Linphone / MicroSIP，账号 = 注册时的分机号 + 密码。
2. 拨 `*62`。
3. STT → 同一套 Agent（精简工具）→ TTS。支持打断（barge-in）。
4. 产生 `type=call` 的线程，出现在右侧「通话记录」，不进左侧对话列表。

设置 → SIP：只显示分机号和拨打说明，**不显示密码**。文案称「重新登录一次就会显示」密码。

### 13.2 Alfred 打给你（呼出）

触发：对话里要求打电话、提醒 `delivery_method=call`、主管分心升级。

经 LiveKit SIP trunk 打到用户分机。语音中禁用「再打一通」以免套娃。

### 13.3 本机唤醒词（Ear）

本机麦克风听到唤醒词（`alfred_fast`，回退 `hey_jarvis`）→ 提示音 → 加入本地 LiveKit 房间 → 语音对话。约 10 秒静音挂断。

依赖 Ear 进程 + 本地 `LIVEKIT_WS_URL`。WebUI 无对应开关页。

### 13.4 通话记录面板

呼入 / 呼出标签；点开进入 `/chat/{id}`；可删除线程；今日无通话有空态。

### 13.5 网页「语音设置」

占位，没有可测的 TTS 选项。

## 14. 屏幕与主管（Supervisor）

两层开关（聊天右上快捷开关 + 设置 → 主管），**按明确绑定的账号保存，默认关闭**。首次使用在本机页面点击“绑定到当前登录账号”，并在 Windows 确认框授权，无需手动配置环境变量；详见 [屏幕监控部署与验证](屏幕监控.md)。

| 开关 | 含义 |
|---|---|
| 主动记录 `recording_enabled` | 请求启动 Screenpipe 采屏/OCR，不录音；页面另行检测实际运行状态 |
| 智能监督 `smart_supervision_enabled` | 在记录之上，定期用 LLM 判断是否分心，并可能来电 |

Supervisor 每 3 秒读取用户级开关，页面每 5 秒检测真实状态。旧的全局开关不再沿用。

**智能监督逻辑（可测前提）：**

1. Supervisor 进程在跑，Screenpipe 在跑。
2. 目标用户 = 本机明确确认绑定的账号（也支持管理员用 `SCREEN_MONITOR_USER_ID` 预配置），未绑定或账号不存在时拒绝采集。
3. 该用户有已到 `scheduled_start_at` 且仍 pending 的待办。
4. 按 `SUPERVISOR_INTERVAL`（默认 600 秒）取最近 `SUPERVISOR_OCR_WINDOW_MINS`（默认 10 分钟）OCR。
5. LLM 输出：`NORMAL` / `GENTLE_REMINDER` / `STRICT_WARNING` / `SEVERE_DISCIPLINE`，后三档会 TTS + 外呼（主管号码默认分机 100）。

Agent 还可调用 `view_screen` / `search_screen_time` / `take_screenshot`，均校验绑定账号。历史查询要求采集已启用且服务健康；即时截图不依赖连续记录开关。无归属的旧录屏不会自动迁移。

## 15. 实时事件

登录后前端挂 `GET /api/events/stream`。用于刷新待办、提醒、主管相关 UI，没有独立事件中心页面。Redis 不可用时事件总线会降级，面板可能要手动刷新才能看到后台变更。

打开任意页会先「正在预热 Alfred」（用 `GET /api/models` 探活），失败可重试。

## 19. 用户隔离与「其实是全局」的设置

**按用户隔离：** 对话线程、待办、提醒、邮件账户、知识库文档、L1 记忆文件、Bark URL、头像、SIP 分机、引导标记。

**全局一份（多用户会互相影响）：**

- 当前 LLM 型号
- 主管两个开关
- 主管盯的人 = 最近登录用户

时区来自环境变量 `TIMEZONE`（`.env.example` 默认 `Europe/London`），影响待办/提醒时间展示与到期判断。

## 20. 建议测试分组

按依赖拆开，避免「没起 Worker 就判提醒坏了」。

### A. 只起 API + LangGraph + WebUI 就能测

1. 注册 / 登录 / 401 跳转 / 退出
2. 改资料、头像、密码
3. 新对话建线程、流式、停止、复制、Markdown
4. 侧栏搜索 / 重命名 / 删除 / 自动标题
5. 对话建待办 → 右侧看见 → 勾选/编辑/删除
6. 对话建提醒（先不必等到期）→ 右侧改时间/删除
7. Memory 四类手工编辑，下一轮对话是否用上 profile/preferences
8. 模型列表与切换（多用户是否互相覆盖，若你认为不该覆盖则记缺陷）
9. 引导弹窗与教程页
10. Agent 头像出现在气泡
11. 附件图片进对话；PDF 附件抽文本（不入库）
12. 知识库上传 md/txt、进度、列表、删除、页内搜索
13. 空态天气卡：先不设位置 / 再设位置

### B. 还要 Redis + Worker

14. 提醒 push 到期（需 Bark）
15. 提醒 call 到期（还需 SIP）
16. SSE：在另一端改待办/提醒，面板自动刷新
17. 待办到期：**不应**收到 Bark；应标记已通知并可能唤醒主管

### C. 还要邮箱

18. 绑定 Gmail/QQ/163/其他；错误密码应拒绝保存
19. 对话列信、读信；右侧面板打开正文
20. 起草 → 确认发送；旧草稿按钮不可用
21. Agent 不能在未确认时发出邮件

### D. 还要知识库图片模型 + 带图 Markdown

22. 入库带图 md，检索结果还原图片
23. 对话「根据我的笔记……」能引用原文和插图

### E. 还要语音栈

24. 聊天麦克风转写进输入框
25. 软电话拨 `*62` 能通话、能打断、通话出现在通话记录且不进对话列表
26. 对话或提醒触发外呼
27. 唤醒词进入本地语音（若在测 Ear）
28. 语音通话中不能读邮件、不能再外呼

### F. 还要 Screenpipe + Supervisor

29. 只开「主动记录」：在采屏，不来电
30. 再开「智能监督」+ 有已开始的 pending 待办 + 故意分心：应升级并来电
31. 无进行中待办：不应来电
32. 对话让 Agent 看当前屏幕 / 截屏问答

### G. 不要当作功能去测

- 设置「语音」分区出 TTS 选项
- 浏览器里接听/拨打 LiveKit
- 待办到期 Bark（当前已关掉）
- 独立 Dashboard
- 暗色主题、PWA
- 聊天 Web 上传 PDF 进知识库（页面对这类文件都不开放）

## 22. 后台 CLI / 运维入口（非 Web 功能，但系统要靠它们）

| 入口 | 作用 |
|---|---|
| `uv run python -m app` | FastAPI `:7788` |
| `uv run langgraph dev` | Agent `:2024` |
| `worker.py` | 到期调度 |
| `supervisor.py` | 分心监测 |
| `livekit_worker.py` / `--local` | SIP / 本地语音 |
| `python -m body.windows_system.ear.ear_service` | 唤醒词 |
| `python -m rag.cli` | 知识库命令行 |
| `start-all.ps1` / `setup.ps1` | 一键安装与启动 |

这些不算「用户功能」，但测试主动提醒、通话、主管时必须确认对应进程在跑。
