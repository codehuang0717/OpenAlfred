# 真实 API 上下文探针（2026-09-27）

## 结论与证据等级

本报告记录修复前的探索数据；后续已将摘要成品限制与生成预算分离，复测见 `context-summary-fix.md`，本报告原始数据保持不变。

使用已配置的 MiMo `mimo-v2.6-pro`，共尝试 **19 次真实 API 调用**（首轮 17 次，修正探针后 2 次），没有自动重试或切换供应商。全为合成材料，只发送工具定义，不执行任何工具，不读取个人记忆或聊天。

这次是探索性测量，不是生产验收。主模型 token 与缓存数据来自供应商 usage；第一轮摘要测量存在探针输出上限漏传的问题，不能将其摘要耗时/成本作为严格生产参数下的新旧策略对照。修正后确认存在摘要长度截断失败，应先解决该问题，再验证完整策略收益。

## 主模型真实结果

每个策略发送相同的准备后消息两次；表中缓存是第二次请求的真实缓存读取量，不是离线前缀代理。首字时间是从主模型开始调用到首个正文片段，不含上下文准备或摘要。

| 场景 / 策略 | 每次主请求输入 token | 重复请求缓存读取 / 输入 | 首字 ms：首次 / 重复 | 直接代码回答命中 |
| --- | ---: | ---: | ---: | ---: |
| short / baseline | 5725 | 5696/5725 (99.49%) | 1549 / 3306 | 2/2 |
| short / tuned | 5542 | 5504/5542 (99.31%) | 1297 / 1853 | 2/2 |
| medium / baseline | 5597 | 5568/5597 (99.48%) | 2266 / 无正文 | 0/2 |
| medium / tuned | 8135 | 8128/8135 (99.91%) | 1898 / 1602 | 2/2 |
| pressure / baseline | 8763 | 8704/8763 (99.33%) | 无正文 / 1674 | 1/2 |
| pressure / tuned | 6017 | 6016/6017 (99.98%) | 2452 / 1789 | 2/2 |

- 中等工具结果不涉及摘要，未受摘要探针问题影响。新版保留中段证据，输入从 5597 增至 8135（约 +45.3%），两次均直接回答正确代码；旧版一次 UNKNOWN，一次返回工具调用但没有正文。
- 新旧相同请求重复时均可接近 99% 命中。这不能证明新版在持续变化的真实会话里也能维持该命中率，本轮没有测持续追加对话的缓存序列。
- 缓存命中不保证单次首字更快：short baseline 从 1549ms 变为 3306ms。模型输出/推理差异、服务负载和网络会影响延迟，两个样本不足以作显著性判断。
- 请求声明了 tool_choice=none，但第一轮仍有两次 finish_reason=tool_calls。没有执行它们。因此“直接代码回答命中”不是生产任务成功率；允许原文回查后旧策略可能也能答对，需付出额外调用。
- 主请求前部使用不同命名空间降低 A/B 相互预热；摘要前缀没有隔离，pressure tuned 的一次摘要读取了 4032 缓存 token，存在顺序影响。

## 摘要测量缺陷与修正验证

第一轮为了读取 usage，探针将摘要链改为 include_raw=True。无网络 HTTP 传输捕获证明：本地 LangChain 的这条 RunnableMap 路径丢失了 ainvoke(max_tokens=1600) 参数；生产 include_raw=False 路径会发送 max_completion_tokens=1600。

因此第一轮 short baseline 的两次摘要约 36.5 秒、pressure baseline 一次约 26.8 秒、pressure tuned 两次约 41.5 秒，都是真实耗时，但受探针参数缺失影响，**不能宣称新版在生产参数下节省了对应秒数**。其中部分摘要输出超过 1600，不代表生产路径忽略预算。

探针现已在构造结构化链之前把上限设在模型对象上，并补充 mock HTTP 测试验证请求体实际含 1600。用剩余额度对 short baseline 复测：

1. 第一次摘要成功：输入 581、输出 1284、缓存读取 576、耗时 14903ms。
2. 第二次摘要发生 LengthFinishReasonError，输出触及长度限制而无法完成结构化解析；主回答未执行，立即停止，未重试。

失败的流式摘要未取得 usage，不能按 0 计费。已取得 usage 的 18 次调用合计输入 **93098**、输出 **9985**、缓存读取 **44224** tokens；这不包含失败调用，也不是账单金额。缓存读取属于输入的子集，不能再次相加。

## 测试范围与下一步

short 为 25 条合成短消息；medium 为中段含代码的长工具结果；pressure 用 12000 总预算主动触发压缩（并非生产默认 65536）。主输出请求上限 1024，摘要请求上限 1600，输出内容目标仍由摘要 schema/token 验证约束。

建议下一步先把“最终摘要长度目标”与“模型生成/推理输出预算”分开设计，明确处理长度截断，再做受控在线复测；不是直接无条件放宽总预算。本次只修正测试探针，未改生产压缩参数，也未触发新的真实调用。

复现（会产生 API 费用）：`uv run python probe_context_api.py --run`。可通过 --case、--policy、--repeats、--max-requests 缩小范围。修正路径审计使用 --case short --policy baseline --repeats 1 --max-requests 3，实际只尝试 2 次就停止。

原始数据：[探索轮](context-api-results-exploratory.json)、[修正后审计](context-api-results-cap-audit.json)。单元测试不调用网络；包含请求额度、输入额度、流式用量和真实请求体上限校验。
