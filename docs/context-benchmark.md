# 上下文策略离线 A/B 测试

日期：2026-09-27。结论：新策略减少摘要调用并保留更多原文，但不是所有场景都减少 token，更不能据此宣称账单或端到端延迟下降。

历史快照说明：下表记录的是摘要生成预算拆分之前的版本。当前生成额度已独立为 4096、成品上限仍为 1600，证据分批大小随之改变，重新运行可能得到不同的摘要次数。此处保留原始结果，不追改历史测量。

## 方法与复现

运行：`uv run python tests/context_benchmark.py`。

- 冻结基线：`tests/fixtures/context_manager_baseline.py`，即本轮调优前的预算规划器，不是更早的原始 last-20 实现，也不参与生产。
- 5 个合成场景，每个策略每次重放使用独立临时 SQLite 数据库。每策略 109 次请求，三次重放共 654 次上下文准备，交替策略顺序。无个人数据、无网络、无真实模型费用。
- 工具定义使用实际 ALL_TOOLS，系统指令使用实际 AGENT_SYSTEM_PROMPT；日期、天气与用户资料为合成数据。总预算固定 32768，输出预留 4096，安全余量 2048。
- 两边使用相同的确定性摘要替身。它记录真实摘要请求结构的估计 token，但不评估真实摘要语义质量。新策略 trigger=.90、target=.65、inline=8192。
- 每次准备均检查预算、工具组完整性和最新用户请求原文保留。工具场景还检查最新结果中间的失败证据是否直接可见。

## 信息保留与成本取舍

- 中等工具结果：最新结果的中段失败证据直接可见率从 0/12 升至 12/12；旧策略把它们全部变成首尾预览。新策略输入量约翻倍是保留原文的代价，不应隐藏。
- 超大工具结果：两边中段直接可见率都是 0/12，仍需要 read_context_excerpt 回查。配套单元测试验证分页与原文一致，但本基准没有模拟自主模型决定回查，也不计算额外回查轮次成本。
- 长对话：摘要调用从 31 次降至 4 次，触发摘要的请求从 30 次降至 2 次；输入增加约 27%。少一次摘要意味着少一次额外模型调用，但真实节省时间未经在线测量。
- 短聊天、短工具链避免不必要摘要，输入量略降。不能外推到所有真实用户对话。

## 缓存指标的边界

前缀指标是规范 JSON 序列化后的相邻请求最长相同 token 前缀占累计序列化输入的比例，不是供应商返回的缓存命中率，也不是计费折扣。工具定义排在前面是本基准的固定约定，不保证匹配供应商实际模板。SDK 还可能重排系统消息，缓存 TTL、路由和最小长度也未建模。

移动时间/天气到末尾、减少摘要重写提升了此前缀代理，但不能因此计算真实账单。新增 context.model_usage 日志分别记录主模型供应商返回的 input_tokens、output_tokens、cache_read_tokens；缺失值保留 null。call_elapsed_ms 是完整调用耗时，不是 TTFT；摘要真实 usage 尚未纳入这条主模型日志。

## 已应用的策略

取消消息条数触发；90% 输入预算触发、压到 65% 目标；稳定指令与资料在前，实时上下文在末尾；8192 token 内工具原文保留；哈希键计数缓存上限 2048 条。原有配对、用户隔离、错误显式暴露及原文回查机制保留。

当前建议把它视为减少摘要打断、改善信息保留的方案，而不是已证明更便宜的方案。真实成本结论应在后续受控在线测试中比较供应商计费、首字延迟、回查次数和任务正确率；本次没有调用付费模型或修改个人记忆。

验证：后端全量 160 项通过。策略回归包含短聊不再摘要、摘要后留余量、时间与稳定指令分离、中段证据保留、计数缓存有界，以及真实 usage 未知值处理。
