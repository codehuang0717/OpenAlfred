# 上下文压缩与预算

## 调用流程

`load_context → prepare_context → agent → tools → prepare_context`。
每次主模型调用前（包括语音、每轮工具返回）重新计算预算；不再按最后 N 条消息硬切。
最终回答后仍执行原有长期记忆提取，它不是后台任务，但不再追加会话摘要。

预算包含系统提示、注入记忆、天气、工具定义、滚动摘要、消息、输出预留和安全余量。
默认总预算 65536，输出预留 4096，安全余量 2048。主模型请求也设置对应输出上限。
计数使用 `cl100k_base` 估算，并非所有供应商的精确 tokenizer；应按实际模型窗口调整预算和余量。
图片按每张 8192 tokens 预留，不下载图片计数；其他未支持的多模态格式明确报错。

## 保留与压缩规则

- 一个 AI 工具调用及其全部并行结果是不可拆分的消息组；缺失、孤立、重复配对均报错。
- 最近两个消息组不压缩，最新用户请求始终保留原文。单条请求太大时要求拆分，不静默截断。
- 超过可用输入预算的 90% 时，将较早完整组归入滚动摘要，目标降至 65%，给后续轮次留余量。受保护的最近消息组优先，目标不是硬限制。
- 摘要分开记录目标、有效约束、确认结果、待办、关键事实、证据引用，替换而非追加旧摘要。
- 默认保留不超过 8192 token 的工具原文；更大的结果使用不超过 1200 token 的稳定预览。预算不足时归纳旧消息，原始图历史不变。
- `read_context_excerpt` 根据 `ctx:index:hash` 引用分页读回原文，只访问当前已认证线程。
- 新摘要使用明确配置的模型，不因错误切换供应商。超时、超长、空摘要、非法结构、并发冲突均停止本轮主模型请求，保留已提交摘要。

## 持久化与兼容

新表 `context_compactions` 按 `(user_id, thread_id)` 隔离，保存摘要、覆盖游标、历史哈希和版本号。
更新使用版本比较，避免并发覆盖；编辑或回放历史导致哈希不符时，从当前原始历史重新规划。
旧 `thread_memories` 不删除但不再注入；首次需要压缩时从原文建立新版摘要。
原始消息继续保存在 LangGraph 历史中，保证回查和长期记忆提取游标有效；本功能不负责清理磁盘历史。

## 配置与诊断

设置见 `.env.example` 的 `CONTEXT_*` 和 `MAX_CONTEXT_TOKENS`。
`MAX_CONTEXT_MESSAGES` 只为旧接口保留，不再触发压缩；旧 `SUMMARY_THRESHOLD` 已停用。
稳定指令和用户资料放在前部，实时日期、天气放在请求末尾，不持久化进历史，不更改工具调用配对。
文本计数使用最多 2048 条的摘要哈希缓存，仅缓存计数，不保存用户原文或模型结果。
默认摘要模型 `mimo`，需要配置对应密钥；可通过 `CONTEXT_SUMMARY_MODEL` 明确选择其他已支持模型。
`CONTEXT_SUMMARY_INPUT_TOKENS` 包含摘要请求输入、结构定义、输出预留和安全余量。
成品摘要长度由 `CONTEXT_SUMMARY_TOKENS=1600` 验证；API 生成额度单独使用 `CONTEXT_SUMMARY_GENERATION_TOKENS=4096`，为结构化生成及供应商计入的额外输出留空间。两者不可混用。
摘要总请求预算仍为 12000：增加生成预留会减少每批证据量，不会放宽主模型总预算。更大生成上限可能增加单次成本，较小批次也可能增加摘要次数。
摘要生成保留 60 秒超时；长度截断或超时明确报错，不追加重试、不保存残缺结果、不切换供应商。严格模型工厂同时关闭 LangChain 和已初始化 SDK 客户端的自动重试。

日志 `context.prepared` 记录压缩前后估计 token、工具定义占用、覆盖数量、预览数、摘要调用数和耗时。
`context.model_usage` 另行记录供应商实际返回的主模型输入、输出及缓存读取 token；缺失字段为 null 而非 0。调用耗时不等于首 token 延迟。
`context.failed` 记录失败类型；前端隐藏内部摘要流。按需压缩仍会增加首 token 等待时间，大历史首次迁移尤其明显。

部署时重启 FastAPI 以创建新表，再重启 LangGraph 和前端；不需要删除数据库或个人记忆。
离线回归：`uv run python -m unittest discover -s tests -p "test_*.py"`。
测试使用临时数据库和模拟模型，覆盖预算、配对、证据、回查、失败保护和隔离；真实供应商的摘要质量仍需实际会话验证。

离线策略对照：`uv run python tests/context_benchmark.py`。冻结基线只存在于 `tests/fixtures/`，不参与生产；详见 `docs/context-benchmark.md`。
