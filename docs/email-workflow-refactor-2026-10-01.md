# 邮件发送重构：第一阶段

邮件先保存为可编辑草稿，用户在界面核对后确认发送。聊天卡片与邮件面板打开同一个草稿编辑器，后台发送任务保存确认时的完整内容和结果。

## 已实现

- 编辑发件邮箱、单个收件人、主题、纯文本正文；600ms 自动保存。浏览器会话备份保留尚未保存的输入，刷新后可恢复。
- 草稿按用户隔离，修改必须匹配 `revision`。并发修改返回 409，界面保留本地输入，可复制为新草稿或明确加载最新版本。
- AI 使用 `create_email_draft` 保存草稿，聊天历史保存 `draft_id` 引用；主模型后续失败也不丢草稿卡片。`get_email_draft` 读取最新版本，`update_email_draft` 保存独立修改建议，用户采用后才更新原草稿。
- 建议采用需要匹配原草稿版本，不会发送；已采用建议锁定为 `adopted`，不能作为另一个草稿直接发送。
- 用户确认版本后创建 SQLite 发送任务，冻结发件账号、地址、主题、正文和 Message-ID。相同请求标识、同版本并发点击返回同一个任务。
- FastAPI 生命周期启动邮件 worker；领取任务、租约、心跳和结果写入均持久化。排队中可以取消，开始提交后不能撤回。
- 发送记录展示每次尝试的内容快照。复制旧记录保留该次内容；原邮箱已移除时需重新选择发件账号。
- SMTP 使用现有 aiosmtplib；465 使用 TLS，其他配置端口显式 STARTTLS。验证邮箱与发送行为一致，不重复升级 TLS。
- SMTP 接受提交后先记录结果，再退出连接。QUIT 失败不会把已接受的邮件判为发送失败。
- 邮件事件只发送给资源所有者。前端沿用 TanStack Query 的账号缓存与失效机制，活动任务也会轮询更新。

## 结果含义

| 状态 | 含义与后续操作 |
| --- | --- |
| `draft` / `proposal` / `adopted` | 可编辑草稿 / 待采用建议 / 已采用且锁定的建议 |
| `queued` | 尚未开始发送，可以取消 |
| `sending` | 后台正在连接或提交，不能撤回 |
| `accepted` | SMTP 服务器已接受提交；不等于收件人已收到 |
| `partial` | SMTP 返回部分收件人被拒绝，保留结果，不自动重发 |
| `failed` | 明确未提交或明确被服务器拒绝，可检查并手动确认重试 |
| `unknown` | 提交后连接断开或服务中断，可能已发送；锁定且不自动重发 |
| `cancelled` | 排队任务已取消，可编辑草稿后重新确认 |

应用请求可以去重，SMTP 无法保证端到端恰好发送一次。丢失最终确认时保留 `unknown`，由用户核对；系统不会猜测成功，也不会自动重试未知结果。发送历史保留旧尝试，明确失败或取消后的重试使用新请求标识。

## 接口与兼容性

- `GET/POST /api/email-drafts`：列出或创建草稿。
- `GET/PATCH /api/email-drafts/{id}`：读取或按版本保存。
- `POST /api/email-drafts/{id}/adopt`：按原版本采用建议。
- `POST /api/email-drafts/{id}/send`：按版本与请求标识确认，返回 202 和持久任务。
- `GET /api/email-send-jobs`、`GET /api/email-send-jobs/{id}`、`POST /api/email-send-jobs/{id}/cancel`：发送历史、状态与排队取消。

启动时增加 `email_drafts` 与 `email_send_jobs` 两张表，不修改已有邮箱凭据。无需新增环境变量或第三方依赖。OpenAPI 与前端类型由现有生成脚本同步。

旧版直接发送接口 `/api/emails/send` 已废弃并返回 410，旧页面需要刷新。旧 JSON 草稿没有可靠发送历史，因此只提供用户主动“导入并编辑”；不会批量导入或自动发送。相同历史卡片导入使用稳定请求标识，重复打开不会重复建草稿。旧直接发送服务已移除。

本阶段不包含附件、抄送/密送、富文本、定时发送和送达回执跟踪。会话关联由 LangGraph 消息中的草稿引用保留。

## 验证

- `uv run python scripts/check_repo.py`：Ruff 与 OpenAPI 一致性检查通过。
- `uv run python -m unittest discover -s tests -p "test_*.py"`：358 项通过，覆盖所有权、版本冲突、并发发送、建议采用、历史回放、事件隔离、SMTP 明确失败、未知结果、租约与清理失败。
- 前端 `npm test`：78 项通过；`npm run check` 与 `npm run build` 通过。
- `npm run test:browser`：15 项通过，覆盖保存恢复、版本冲突、重复确认、发送历史、AI 建议、账号切换和手机布局。

SMTP 全部使用模拟对象，未发送真实邮件。浏览器使用合成数据，未调用真实模型或读取个人邮箱。前端仓库 `docs/email-workflow.md` 包含已检查的桌面与手机截图。
