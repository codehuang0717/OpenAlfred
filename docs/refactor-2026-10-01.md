# 重构分支改造说明

后端 `OpenAlfred` 和前端 `OpenAlfred-WebUI` 均使用 `重构` 分支。本次覆盖指定的七项改造，保持现有工具时间线、附件、语音输入、邮件确认卡、私有图片和后台编码任务的业务协议。

| 项目 | 实现 | 业务边界 |
| --- | --- | --- |
| 聊天流 | 使用已安装的 LangGraph SDK 1.8.8，删除手工 SSE 解码 | SDK 处理分包、UTF-8、事件 ID 和断线续流；ChatSession 保留工具时间线及服务端历史核对 |
| 聊天 UI | assistant-ui 0.15.22 的 ExternalStoreRuntime、Thread/Message primitives | 外部 ChatSession 仍是消息来源；现有附件和语音输入组件保留 |
| 流式 Markdown | Streamdown 2.7.0 替换 ReactMarkdown 聊天渲染 | 未完成语法修复；继续支持公式、表格、代码复制、邮件卡和鉴权图片 |
| 聊天滚动 | use-stick-to-bottom 1.1.6 | 到底部时跟随增量内容；向上阅读时保持位置，提供跳到最新按钮 |
| 业务数据请求 | TanStack Query 5.104.0 | 按账号缓存、请求去重、取消、乐观回滚、后台轮询；统一合并 SSE/工具刷新 |
| API 类型 | FastAPI OpenAPI → openapi-typescript 7.13.0 → openapi-fetch 0.17.0 | 路径、请求体、查询参数和 JSON 返回类型从后端生成；表单文件为 Blob 类型 |
| 仓库代码检查 | 后端 Ruff 0.16.9 + OpenAPI 一致性；前端类型、ESLint、API 一致性 | 默认静态检查；单元测试和浏览器测试在整合边界按需运行 |

## 请求与账号隔离

- JSON 和表单上传共用鉴权、错误处理和 AbortSignal。业务写请求不自动重试，避免重复创建任务或重复发送邮件。
- 401 仅能清除发起该请求时使用的凭证；旧请求不能清除后来登录的新账号。
- 登出或切换账号时清空 Query 缓存和本地 ChatSession，终止本地流读取。页面卸载仍允许后台运行继续。
- 同账号更换 token 也会重新建立查询观察者和 SSE 连接。
- SSE 与工具事件在 100ms 窗口内合并资源失效通知。各业务 hook 不再分别重复监听刷新事件。

## API 合同

后端新增 `src/schemas/responses.py`，为现有 JSON 接口补充成功响应的 OpenAPI 描述；声明使用路由的 `responses` 参数，不改变已有运行时序列化或删减返回字段。

生成链：

```text
FastAPI routes + Pydantic schemas
  -> OpenAlfred/docs/openapi.json
  -> OpenAlfred-WebUI/src/lib/api-schema.d.ts
  -> OpenAlfred-WebUI/src/lib/api.ts
```

检查真实返回后修正了几处原有手写类型偏差：SIP 账号可以为空；资料创建时间可以为空；摄入任务 result/error 明确包含 null；小程序列表和详情返回字段不同；天气值也可能为空。

默认两个仓库相邻。后端位置不同时，前端生成与检查命令可传 `--backend`：

```powershell
npm run api:generate -- --backend D:\path\OpenAlfred
npm run api:check -- --backend D:\path\OpenAlfred
```

## 验证边界

后端 336 项 unittest、前端 74 项单元测试和生产构建已验证。6 项浏览器整合用例覆盖：响应未结束且历史尚未回读时首段可见、流式代码/公式/表格、私有图片携带鉴权、邮件草稿确认、向上阅读与恢复跟随、请求去重、SSE/工具刷新合并、账号切换/凭证刷新、失败删除回滚与单次写请求、首次发送的并发点击。

Ruff 当前执行语法、无效表达式和未定义名称检查（E9/F63/F7/F82），避免把历史格式风格整改混入功能重构。ESLint 保留现有规则；图片优化等已有建议仍是 warning。浏览器测试验证模拟服务的兼容性，未使用真实模型或 Windows 语音设备做端到端调用。

## 首段一次性显示修复

检查当前安装的 `langgraph_api/stream.py` 后确认：HTTP API 的 `messages` 模式把节点信息放在独立的 `messages/metadata` 事件中，`messages/partial` 只包含累计消息；原前端却按 `[message, metadata]` 解析，中途文本被节点过滤丢弃，最后才从历史记录显示回复。

改为请求 `messages-tuple`，使每个增量携带节点信息；`AIMessageChunk` 按真实增量追加，保留重复 token、Markdown 分隔符和缩进。浏览器 fixture 按后端实际两种协议发送事件，新增保持 SSE 未结束的用例；该用例在修复前失败，修复后通过，避免只检查最终完整回复。
